# 13 — Profile Sections (Bagian Profil)

Sub-pages of the public-facing village profile. Each section has a name, endpoint slug, and rich-text body.

---

## 1. Purpose

Manage rich-text sub-pages under the village profile (e.g. "Sejarah Desa", "Geografi", "Demografi", "Potensi Desa"). Each section becomes a URL on the public site.

---

## 2. Routes

| Path | Name | Breadcrumb | Guard |
|------|------|-----------|-------|
| `/profile/sections` | `ProfileSections` | Bagian Profil | `requiresAuth` |
| `/profile/sections/create` | `ProfileSectionCreate` | Tambah Bagian Profil | `requiresAuth` |
| `/profile/sections/:id/edit` | `ProfileSectionEdit` | Edit Bagian Profil | `requiresAuth` |

These are nested under the `/profile` URL family but managed by a separate service.

## 4. API Endpoints

| Method | Path | Body / Params | Used by |
|--------|------|---------------|---------|
| `GET`    | `/profile?page&limit&search&section_name&state` | — | List view |
| `GET`    | `/profile/{id}`                                | — | Form view (edit) |
| `POST`   | `/profile`                                     | `{ section_name, content, endpoint?, state? }` | Form view (create) |
| `PUT`    | `/profile/{id}`                                | `{ section_name?, content?, endpoint?, state? }` | Form view (edit) |
| `DELETE` | `/profile/{id}`                                | — | List view (delete) |
| `GET`    | `/profile/sections/names`                      | — | Section-name dropdown |

Public endpoints (`/public/profile/...`) defined in swagger but not consumed by the admin.

---

## 5. Data Model

```ts
type ProfileSection = {
  id: string
  section_name: string         // human label
  endpoint: string             // auto-generated slug like /profile/page-x8h3k
  content: string              // HTML produced by Quill
  state: 'draft' | 'published' // (or similar — confirm)
  created_at?: string
  updated_at?: string
}
```

---

## 6. Behaviors

### 6.1 List (`ProfileSectionListView.vue`)

- Filter row: search input, section_name dropdown (from `/profile/sections/names`), state dropdown.
- Table columns: Nama Bagian | Endpoint | Status | Aksi.
- Pagination computed as `Math.ceil(pagination.total / pagination.limit)` — minor inconsistency vs other views (see `00-architecture.md` §10).

### 6.2 Form (`ProfileSectionFormView.vue`)

- Mode from `route.name`.
- Fields:
  - `section_name` — `<select>` populated from `/profile/sections/names`.
  - `endpoint` — **read-only**, auto-generated by the backend (shown as a code-style badge).
  - `content` — `RichTextEditor` (Quill).
  - `state` — radio (draft / published).
- Save → service call → success toast + navigate back to list.

### 6.3 Delete

- Confirm dialog → `DELETE /profile/{id}`.

---

## 7. UI Notes

- Endpoint is shown as a small monospaced badge so the admin can see what URL it will be served at.
- Quill editor fills most of the form page.

---

## 8. Notes & Gotchas

- **Section-name list** is fetched once on mount; if the list grows dynamically the dropdown does not refresh automatically.
- **Endpoint is read-only** — the admin cannot customize the URL slug. Confirm with backend that collisions are handled.
- **No reordering** — sections render in the order returned by the backend.
- **No duplicate `section_name` prevention** in the UI — backend should enforce uniqueness.
